## 2. 我们增加的扩展（按模块）

> 详细规则与[ASSUMED] 记录在 [docs/history/0.0.1.md](history/0.0.1.md)（§35.1–§35.14）。

### 2.1 三种模式与 2V2 房间

- 对外模式名：**独立狩猎**（单人）/ **同盟狩猎**（1–4 人合作）/ **狩猎模拟**（2V2）。
- `ROOM_MODES = solo / coop / versus`；2V2 固定两队、每队 2 人（座位 0/1 与 2/3）。
- **共享生命池**：每队一条池，扣血先落池，成员 `ps.lp` 只是拆分；UI 显示池本身。
- 按队禁盟约、按队公共棋池、按队机变轮取、按队重刷投票。
- 座位交换（换座位=换队）、空位 AI 补齐、掉线保留座位 10 分钟、离开交 AI 托管。
- 狩猎起始回合：每局从 R4 / R5 / R6 抽一个（`contestStartRound`）。

### 2.2 狩猎期（`PHASE.CONFRONT`）

- 每个非关底回合的休整期结束后进入：**选目标 10 秒**（队内先选先得，四人一对一配对）→ **定制怪物**（窗口=本轮休整期，全员提交即结束，超时 AI 自动投放）。
- 预算 = 本轮波次总价值 × 替换比例 × 2；比例 **5% 起步、每回合 +2%、上限 15%**；**R13 最终狩猎固定 50%**。
- 7 类「特训敌人」（特异/飞行/频次/元素/持续/隐匿/折射），可跨类型混搭，只受总价值约束。
- 价值表 = 属性分 + 特性分（1/2/3 档，特性恰好占 30%）。
- 出怪位置靠前/靠中/靠后（25/50/75%）；逐只选上/下路；对面投放的怪带淡红描边与 `P<n>` 来源标记。
- **投放怪漏过不扣血、不破坏完美作战**；只有击杀才结算赏金。
- 狩猎期结束 **5 秒名单公示**（谁给谁派了什么、赏金多少）。

### 2.3 赏金与坎诺特

- 赏金只算**投放怪**；前 4 次固定 1 / 1 / 2 / 2，第 5 次起按「价值 ÷ 波次价 × 本轮收入」实时结算；**R13 固定 25**；整数向下取整。
- 赏金**不进金币**，记在商人**坎诺特**账上（每人一份、跨回合、重连不丢）。
- 取钱比率：R1–R8 20% / R9 30% / R10 起每回合 +5% / **R15 100%**；首次 ceil、之后 floor；每回合上限 4，R15 不限。
- 面板 1 / 2 / 4 / 全部 四档，写明消耗多少赏金。

### 2.4 事件期（狩猎词条）

- 一局 **3 次**：E1 = 首个狩猎轮、E2 = E1+4、E3 = R13。
- 每次：我方词条四选一（对面 A / 对面 B / 队友 / 自己；**同一目标一局只能用一次**；给自己幅度 ×2）+ 怪物词条独立抽取。
- 我方 24 条、怪物 12 条，局内不重复；概率 E1 15/45/40、E2 30/40/30、E3 45/30/25（怪物 35/40/25、25/40/35、20/35/45）。
- 每次怪物词条附带 **10–25% 强力属性**（獠牙/厚皮/坚壳/疾行），只改敌人面板，不重算赏金。
- **词条持续 4 回合**（`picked … picked+3`），到期自动失效；历史与公示仍显示全部 3 次。
- 环境 buff 乘区：各来源独立相乘；攻速/技力等加减值先上面板。
- UI：事件面板 + 5 秒公示 + **P4 头像下方的「本回合词条」常驻条**（无词条显示「暂无」）。

### 2.5 同盟狩猎（合作版）

- 1–4 人，系统按同一套狩猎节奏**给每名存活玩家各投放一份**（总价值两两不同、类别轮转），直接插入波次。
- 同样有坎诺特、事件期、**5 秒投放公示**；没有对手，所以没有「赏金偷取」与对手隐藏。

### 2.6 终局与结算

- **R14 最终攻势 → R15 隐秘核心**；**R16「终焉核心」整块删除**，Boss 链止于 R15。
- 2V2：每队各打各的领袖；R15 进入门槛按队判定（存活成员激活层数总和 **> 600**，共享池 > 1）。
- **4:5 时间判定**：R14 占 4 份、R15 占 5 份，比较剩余时间占比；同分比共享生命池，再同分用折算分；双败；按队判定。
- 结算页重做：队伍卡、赏金收入/取款、排名、里程碑、观战入口。

### 2.7 信息与观战

- R4–R13 对手不可见（存根行仍画共享生命池），**R14 起公开**。
- 观战席 **2 名**，从第一回合起可见所有人，不受上述限制。

### 2.8 社交与运维

- 局内聊天（Enter、3 秒冷却、单条 80 字、服务端清洗 + 违禁词过滤、对局转写落盘）。
- 全服通知横幅（10 秒自清、可关闭）；房间列表 API（仅回环）+ 回收接口。
- 快速匹配：房主开放后，一键进同难度、未开局、有空座的房间。

### 2.9 客户端体验

- 干员素材预取（头像 + Spine，去重、限量、失败不抛）。
- 伤害/治疗统计（回血按来源速率归给提供者）。
- 画质自动调节 + GPU 自动降档；棋盘 3D/2D 强制切换；角色模型开关。
- 过场延迟可环境变量覆盖（`SP_DELAY_ROUND_START` 等；默认回到官方的 2000 ms，以容纳 0.3.1 的回合开始板）。

### 2.10 只在服务器侧、不进仓库

- 账号 / 云存档 / 成就：`local-ext/patches/hunt-account-ach/`（服务器补丁，仓库 0 引用）。
- AstrBot 插件镜像：`local-ext/from-server/02-astrbot/`。
- 发布包/解压目录名：`Hunt-Simulation`（工具同时**兼容读取**上游的 `Stronghold-Protocol/` 命名）。

## 4. 怎样同步官方文档（可复用流程）

### 4.1 先定基线

```bash
git fetch --depth=500 upstream refs/tags/v0.2.6:refs/tags/up-v0.2.6 \
                                refs/tags/v0.3.1:refs/tags/up-v0.3.1
git merge-base HEAD up-v0.3.1        # 必须是官方 v0.2.6 的提交
```

本仓库是 **shallow** 克隆，边界正好是 `v0.2.6`；`merge-base` 对得上才能做三方合并。

### 4.2 三方合并

```bash
git switch -c sync/v0.3.1
git merge --no-ff --no-commit up-v0.3.1
git diff --name-only --diff-filter=U    # 冲突清单
```

对每个冲突取三个版本：

```bash
git show :1:<file>   # 共同祖先（官方 0.2.6）
git show :2:<file>   # 我方 fork
git show :3:<file>   # 官方 0.3.1
```

### 4.3 文档落点规则

代码改完后，文档按四处同步（缺一处 `test/docs-consistency.test.js` 会红）：

| 落点 | 写什么 |
|---|---|
| `README.md` | 对外功能一览、下载体积、操作、版本徽章 |
| `docs/PLAYING.md` | 玩家规则（数值、流程、判定） |
| `docs/design/*.md` | 规范层（match / client / network / engine） |
| `docs/history/0.0.1.md` | 本 fork 的决策、`[ASSUMED]`、测试清单 |

另外：

- 上游新增的**事实修正**必须并进来（例：0.3.1 的「语音语言 中文/日本語/English/한국어」、凯瑟琳【定向投放】的突变细胞）；
- 章节编号不能和上游撞车（上游占 §32/§33/§34，我们用 §35）；
- 文档里的相对链接必须能在仓库里解析（`test/docs-paths.test.js`）。

### 4.4 版本与 changelog

```
shared/constants.js   APP_VERSION = 0.3.1   FORK_VERSION = V0.0.1
package.json          version = 0.0.1  upstream = 0.3.1
package-lock.json     version / packages[""].version = 0.0.1
CHANGELOG.md          第一行 ## V0.0.1（0.3.1） — 日期
README 徽章           version-0.3.1 / fork-V0.0.1（0.3.1）
```

`test/version.test.js` 会同时校验这几处。

### 4.5 i18n 合并规则

1. 以**上游包为底**，把「我方有、祖先没有」的 key 追加进去；
2. 两边都有的 key：我方新增的用我方值，否则用上游值；
3. 上游已删除、且代码不再使用的 key 要删掉（`test/ui/versus-text.test.js` 的 R13 会扫）；
4. 术语按语言固定：ja 的「特质」= **特質**，「卫戍能力」= 堅守特性；带标签的文案只出现一次标签（如 `[Foresight]`）。
5. 必须跑：`node tools/i18n.mjs check --all --strict`（4 包 100%）。

### 4.6 golden

```bash
npm run golden          # 先看差异
npm run golden:update   # 确认差异是预期（上游 sim 改动 / 我方玩法改动）后再更新
npm run golden          # 复验
```

golden 变更必须在提交说明里写清楚是哪类改动（本仓库约定，见 `test/golden/README.md`）。

### 4.7 验收清单

```bash
node --check <改动的 .js>                 # 或全量脚本
node --test "test/match/*.test.js"
node --test "test/ui/*.test.js"
node --test test/version.test.js test/i18n.test.js \
             test/docs-consistency.test.js test/docs-paths.test.js
npm run golden
```

本地全绿后，才允许提交/推送；**部署前不得推送**（本仓库的硬规则）。

**Linux（WSL2 Ubuntu，Node 24）全量 `npm test`**：

```
tests 8771 · pass 8703 · fail 9 · skipped 59
```

9 条失败均为环境/时序（缺 `data/local-assets.json` 与本地客户端提取、WSL 冷启动导致脚本沙箱 5s 超时、性能阈值抖动）；把 `SP_SCRIPT_PROBE_MS` 调到 30s 后其中 3 条转绿。**没有任何合并回归。**

**与代码无关的本地环境失败**（在纯净的上游 0.3.1 上同样失败，已对照验证）：

- **符号链接**：Windows 非管理员不能 `symlink` → `EPERM`，影响 `test/studio/*`、`test/plugins/forgeImport`、`asset-index` 等；
  解决：开启「开发者模式」或以管理员运行。
- **AdGuard**：它会给回环 HTTP 响应注入 CSP，导致 `test/plugins/ui.test.js` 的帧 CSP 断言失败；
  解决：关闭 AdGuard 的「过滤 localhost」或暂停保护。
- **素材缺失**：仓库不含 `public/assets`，`assets.test.js`、`local-extract-operators`、`official-tables` 需要本地素材/官方表；
  解决：`npm run setup` / `npm run assets` 后再跑。
- **脚本沙箱超时**：Windows 上子进程冷启动较慢，个别 `script-*` 测试可能超时（上游 CI 用更长超时）。

## 7. 后续

1. **一键更新器（已实现）**：设置 → 游戏更新，从本仓库 GitHub Release 拉目标版本与当前版本的**精简包**做差分，只写变化的文件；未变化的本地文件（含本地补丁）保持原样；接口严格回环。
2. **Forge 兼容层（只做本地/皮肤端）**：`cosmetic`（立绘/模型/语音/皮肤/音频）+ `ui`（本地界面小组件）支持；`content` / `script` / `trusted` **服务端暂不支持**，导入产物保留但不进房间、不执行。
3. **插件开关口径**：公网服永久关闭 `script` / `trusted`，`content` 也暂不启用，只开 `cosmetic` / `ui`。
4. **账号/成就**：继续只走服务器补丁，不进仓库。
